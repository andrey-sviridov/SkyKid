# Пакет клинической проверки SkyKid

Review ID: `SKYKID-CLINICAL-001`  
Версия политик: `safety-1.0-draft`  
Статус: ожидается внешняя проверка  
Целевая возрастная группа: 0–12 месяцев  
Язык пользовательских текстов: русский  
Дата технической сверки источников: 23 июля 2026 года

## Назначение

Документ предназначен для письменной проверки лицензированным педиатром. Он не является клиническим заключением и не должен переводиться в статус `approved` разработчиком или автором продукта.

Рецензент проверяет:

1. допустимость пользовательских формулировок;
2. отсутствие ложной точности и опасных обещаний;
3. возрастные и медицинские исключения;
4. продуктовые пороги, для которых нет универсальной клинической нормы;
5. пригодность сообщений для выбранной страны или региона релиза.

## Граница продукта

SkyKid подбирает одежду по погоде, устойчивым особенностям ребёнка и контексту прогулки. Приложение:

- не диагностирует заболевание;
- не измеряет температуру тела;
- не определяет клинически безопасную длительность прогулки;
- не заменяет индивидуальный план врача;
- не может считать одежду компенсацией опасной погоды;
- не должно называться медицински проверенным до завершения этого review.

## Классы утверждений

| Класс | Значение | Требование |
|---|---|---|
| `official` | текст непосредственно следует официальной рекомендации | проверить русский смысл и применимость в регионе |
| `product_guardrail` | консервативное ограничение SkyKid | отдельно принять, изменить или удалить |
| `thermal_heuristic` | численная модель микроклимата/TOG | проверить допущения и пределы применимости |
| `interaction_safety` | правило безопасного использования коляски/автокресла | проверить действие и приоритет |

## Проверка региона релиза

До согласования необходимо указать целевую страну или юрисдикцию. Рецензент подтверждает:

- корректный способ описать срочное обращение за помощью;
- отсутствие номера экстренной службы, неприменимого к выбранному региону;
- понятность терминов «лихорадка», «ОРВИ», «скорректированный возраст»;
- необходимость локальных ограничений по экстремальной погоде и качеству воздуха;
- допустимость русского перевода официальных рекомендаций.

## Перевод решения в release gate

После письменного решения ответственный за релиз:

1. вносит все согласованные изменения и повторно передаёт их рецензенту;
2. запускает `scripts/validate-clinical-release.sh --print-digest`;
3. переносит имя, лицензию, юрисдикцию, дату, commit и digest в `docs/clinical-review-status.plist`;
4. меняет `status` на `approved`;
5. выполняет Release-сборку.

Любое изменение файла из `docs/clinical-policy-inputs.xcfilelist` меняет digest и снова блокирует Release до повторной проверки.
